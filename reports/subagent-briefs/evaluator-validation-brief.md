# Is there an established norm of validating an evaluator/grader/harness before using it to measure an agent?

**Verdict.** For *programmatic* graders, **yes** — "gold/oracle must pass; no-op/empty baseline must fail" is de facto standard in the major SWE and terminal-agent harnesses, documented in their official instructions, and listed as an explicit checklist item. For *LLM-as-judge* graders, validating against human labels and probing known biases is widely recommended and heavily measured, but is per-project practice, not a field-wide gate. I found **no venue or standards body that enforces evaluator validation universally**.

## 1. Programmatic graders: mandated / recommended sanity checks

- **SWE-bench ships gold-patch validation as its documented install check:** `swebench eval verified --gold -i sympy__sympy-20590 --run-id validate-gold`, with a harness-reference section titled "Verifying Gold Patches" using `--predictions_path gold`. — [SWE-bench README](https://raw.githubusercontent.com/SWE-bench/SWE-bench/main/README.md), [Harness Reference](https://raw.githubusercontent.com/SWE-bench/SWE-bench/main/docs/reference/harness.md)
- **The grader fails closed, with an explicit empty/no-op guard:** it flags `APPLY_PATCH_FAIL`/`RESET_FAILED`/`TESTS_ERROR`/`TESTS_TIMEOUT` and returns not-resolved when the patch is `None`, the status map is empty, or a `SUITE_RAN` regex sees no evidence the suite executed — the code notes that under `FAIL_ONLY` "an absent test counts as success," so otherwise "a suite that never started … scores every F2P test as resolved." — [grading.py](https://raw.githubusercontent.com/SWE-bench/SWE-bench/main/swebench/harness/grading.py)
- **FAIL_TO_PASS / PASS_TO_PASS are computed by running tests before and after the gold patch.** SWE-bench's Stage III logs results before vs. after the non-test content, discards instances with no fail→pass test or with install/runtime errors, and marks an instance resolved only if F2P = 1.0 **and** P2P = 1.0. — [SWE-bench (arXiv 2310.06770)](https://arxiv.org/html/2310.06770v3), [grading.py](https://raw.githubusercontent.com/SWE-bench/SWE-bench/main/swebench/harness/grading.py)
- **Leaderboard rules encode evaluator integrity:** pass@1 required; use of `PASS_TO_PASS`/`FAIL_TO_PASS`/`hints` forbidden; browsing safeguards disclosed; `swebench submit verify` re-derives every verdict from recorded logs, and a "verified" checkmark requires an independent rerun on a random subset. — [Experiments README](https://raw.githubusercontent.com/SWE-bench/experiments/main/README.md), [checklist.md](https://raw.githubusercontent.com/SWE-bench/experiments/main/checklist.md)
- **Terminal-Bench defines "Solvability" as an oracle run passing all tests, and checks the negative case.** Each task's oracle solution "when executed, causes all test cases to pass," and on submission "an automated workflow ran the task's oracle solution … other checks verified the absence of common failure modes (e.g., a no-op 'dummy' agent should fail the task)," plus three human reviewers and an adversarial exploit agent. — [Terminal-Bench (arXiv 2601.11868)](https://ar5iv.labs.arxiv.org/html/2601.11868)
- **Terminal-Bench-Science makes it a hard CI gate:** `harbor run … -a oracle` must reach 100% reward (reward = 1.0) and the `nop` agent must score exactly 0; `/validate` runs "similarity, Docker build, oracle, nop." — [CONTRIBUTING.md](https://raw.githubusercontent.com/harbor-framework/terminal-bench-science/v0.1.0/CONTRIBUTING.md)
- **Microsoft's Vally is the most explicit codification found: a dedicated `oracle` verb plus a negative control.** `vally oracle` applies a `golden_patch`/`golden_trajectory` and grades it ("If a grader doesn't pass on the correct answer, the grader is wrong"); `--no-golden-input` withholds golden inputs and requires graders to **fail**, flagging any that still pass as "trivially passing" and exiting 1. — [Vally CLI: oracle](https://microsoft.github.io/vally/reference/cli/oracle/)
- **SWE-rebench V2 uses dual-pass execution validation** (test patch → suite; then solution patch → suite), keeps only instances with ≥1 fail-to-pass test, and filters issue clarity with three LLM judges *calibrated against human-verified SWE-bench annotations*. — [SWE-rebench V2 (2602.23866)](https://ar5iv.labs.arxiv.org/html/2602.23866)
- **The practice responds to documented harness failures.** Issue #26: "sometimes gold_patch cannot pass the test." Issue #393: 42 of 61 leaderboard submissions contained ≥1 patch editing the evaluation test file (17 with >10), and asked for "a sanity check on the `predicted_patch` to make sure it has not conflict with the `test_patch` (e.g. through a patch dry run)." — [issue #26](https://github.com/SWE-bench/SWE-bench/issues/26), [issue #393](https://github.com/SWE-bench/SWE-bench/issues/393)
- **Peers that grade by state/function publish no golden-run gate:** τ-bench compares the end-state database to an annotated goal state; AppWorld uses state-based unit tests; OSWorld gives each task an initial-state config plus an execution-based script; WebArena grades "functional correctness"; GAIA ships human-verified unique answers. — [τ-bench (2406.12045)](https://arxiv.org/abs/2406.12045), [OSWorld (2404.07972)](https://arxiv.org/abs/2404.07972), [WebArena (2307.13854)](https://arxiv.org/abs/2307.13854)
- **The ABC checklist makes an oracle solver an explicit item:** T.9, "Providing an automatic oracle solver can help demonstrate the correctness of the task configuration." — [arXiv 2507.02825](https://arxiv.org/html/2507.02825v5)

## 2. LLM-as-judge validation against human labels

- **MT-Bench set the norm and the headline number:** GPT-4 as judge reaches **>80% agreement** with human experts (85% no-tie), matching human–human agreement (81%), while reporting position, verbosity, and self-enhancement biases. — [arXiv 2306.05685](https://arxiv.org/html/2306.05685v4)
- **JudgeBench shows agreement-with-preference is insufficient:** on objective-correctness pairs, vanilla GPT-4o scored 50.86% and GPT-4o-mini 50.00% against a **50% random baseline**; Claude-3-Haiku 33.14% and PandaLM 13.14% (below chance); o1-preview 75.43%. — [arXiv 2410.12784](https://arxiv.org/html/2410.12784v2)
- **Correlation with humans is the standard reported metric:** G-Eval reports **Spearman 0.514** on summarization; Prometheus 2 reports the highest human/GPT-4 correlation and agreement among open evaluators; the LLM-as-a-Judge survey treats reliability as needing "careful design and standardization." — [G-Eval (2303.16634)](https://arxiv.org/abs/2303.16634), [Prometheus 2 (2405.01535)](https://arxiv.org/abs/2405.01535), [Survey (2411.15594)](https://arxiv.org/abs/2411.15594)
- **Terminal-Bench calibrates its own judges against human labels:** 93% Cohen's κ on a 20-trial calibration subset; a GPT-5 judge at 90% agreement (92% precision / 90% recall) against 120 human-labeled traces; command-level judges at 92.4% agreement with a three-annotator majority and 82.0% against 50 annotations. — [arXiv 2601.11868](https://ar5iv.labs.arxiv.org/html/2601.11868)
- **ABC item O.c.1** recommends pilot experiments assessing an LLM judge's accuracy and self-consistency before use. — [arXiv 2507.02825](https://arxiv.org/html/2507.02825v5)

## 3. Known judge failure modes and how to detect them

- **Position bias, measured two ways.** Order-swap consistency on near-identical answers: GPT-4 **65.0%**, GPT-3.5 46.2%, Claude-v1 23.8%, with 30.0%/50.0%/75.0% "biased toward first"; few-shot lifted GPT-4 to 77.5%. Independently, swap-induced conflict rates were **46.3%** for GPT-4 and 82.5% for ChatGPT, with Vicuna's win rate moving **2.5% → 82.5% by position alone**. — [arXiv 2306.05685](https://arxiv.org/html/2306.05685v4), [arXiv 2305.17926](https://arxiv.org/html/2305.17926v2)
- **Verbosity bias, via the "repetitive list" attack:** a padded answer with a rephrased duplicate won **91.3%** of judgments for Claude-v1 and GPT-3.5 but only 8.7% for GPT-4; math-grading failures fell 14/20 → 3/20 with reference-guided judging. — [arXiv 2306.05685](https://arxiv.org/html/2306.05685v4)
- **Self-preference tracks self-recognition:** GPT-4 identified its own summaries with 73.5% accuracy, and example-level Kendall τ between self-recognition and self-preference was **0.41**, rising to 0.74 after fine-tuning; another study estimates GPT-4 self-preference bias at **0.520**, traced to perplexity rather than authorship. — [arXiv 2404.13076](https://arxiv.org/html/2404.13076v1), [arXiv 2410.21819](https://arxiv.org/html/2410.21819v2)
- **Sycophancy under rebuttal:** the same counterargument is more persuasive as a user rebuttal than as a judge prompt — Llama-3.3-70B adopted it 86.0% vs 56.5%, flipping its own correct answer 80.3% vs 43.4%. — [arXiv 2509.16533](https://ar5iv.labs.arxiv.org/html/2509.16533)
- **Prompt/format sensitivity:** paraphrase-equivalent prompts flipped GPT-4o on 8.5% of pairs versus 61.3% for gemini-2.5-flash, with negative Cohen's κ (systematic disagreement); a 15-attack × 8-defense × 13-judge study found no dominant defense. — [JudgeSense (2604.23478)](https://arxiv.org/html/2604.23478v2), [arXiv 2506.09443](https://arxiv.org/abs/2506.09443)
- **Detection tooling:** Judging the Judges scores Repetition Stability, Position Consistency, and Preference Fairness over >100,000 instances (GPT-4 RS 0.97 / PC 0.82); LLMBar supplies 419 curated adversarial pairs where deceptive style misleads evaluators. — [arXiv 2406.07791](https://ar5iv.labs.arxiv.org/html/2406.07791), [LLMBar (2310.07641)](https://arxiv.org/abs/2310.07641)
- **Verifier reward-hacking is widespread:** an audit of five public terminal-agent benchmarks found **>15% of tasks demonstrably reward-hackable** (331 environments, 3,632 exploit trajectories), and LLM-judge detection degraded when chain-of-thought was stripped (AUC 0.97 → 0.92). — [Terminal Wrench (2604.17596)](https://arxiv.org/abs/2604.17596), [guideline paper (2604.28093)](https://ar5iv.labs.arxiv.org/html/2604.28093)

## 4. Reward-model / verifier validation

- **Overoptimization is a measured scaling law, and low error is not enough:** proxy reward keeps rising while gold reward is hump-shaped in optimization distance (best-of-n: d(α−βd); RL: d(α−β log d)), with near-chance reward models below ~2,000 comparisons; uncertainty-weighted ensembling "practically eliminates" overoptimization (best-of-n +70%, robust to 25% label noise); and a proved "error–regret mismatch" shows a low-test-error reward model can still yield high worst-case regret. — [arXiv 2210.10760](https://arxiv.org/abs/2210.10760), [arXiv 2310.02743](https://arxiv.org/abs/2310.02743), [arXiv 2406.15753](https://arxiv.org/abs/2406.15753)
- **SWE-bench's own tests are demonstrably inadequate:** of 251 passing SWE-Agent+GPT-4 patches, **32.67%** were solution leakage and **31.08%** suspicious from weak tests; after filtering, resolution dropped **12.47% → 3.97%**, with 94% of issues predating model cutoffs. — [SWE-Bench+ (2410.06992)](https://ar5iv.labs.arxiv.org/html/2410.06992)
- **Independent adequacy audit:** UTBoost found insufficient tests on 7.7% of SWE-bench-Lite and 5.2% of Verified instances, 345 erroneous patches mislabeled as passed, and ranking changes for 40.9% (Lite) and 24.4% (Verified) of leaderboard entries. — [arXiv 2506.09289](https://ar5iv.labs.arxiv.org/html/2506.09289)
- **Process verifiers fail out of distribution:** ProcessBench's 3,400 human-annotated step-error cases show existing PRMs do not generalize beyond GSM8K/MATH and underperform a PRM plainly fine-tuned on PRM800K; "Let's Verify Step by Step" built 800,000 step-level human labels and reports process beating outcome supervision. — [ProcessBench (2412.06559)](https://arxiv.org/abs/2412.06559), [arXiv 2305.20050](https://arxiv.org/abs/2305.20050)

## 5. Published checklists / guidelines

- **The Agentic Benchmark Checklist (ABC) is the closest thing to a published standard, and it includes oracle validation** — task validity (T.1–T.10), outcome validity (O.a–O.i), reporting (R.1–R.13), including T.9 (oracle solver) and O.d.1/O.d.2 (manually verify test quality; report coverage/complexity). — [arXiv 2507.02825](https://arxiv.org/html/2507.02825v5)
- **Its measured payoff explains the norm:** mis-scoring up to **100% relative**; a trivial empty-response agent scoring 38% on τ-bench; 100% on SWE-Lancer without solving; KernelBench overestimated by 31 points absolute and WebArena by 5.2%; ABC cut CVE-Bench overestimation by 33% absolute; across ten benchmarks, 7/10 violated task validity, 7/10 outcome validity, 10/10 reporting. — [arXiv 2507.02825](https://arxiv.org/html/2507.02825v5)
- **Terminal-Bench states Specificity / Solvability / Integrity as explicit verification criteria**, backed by a contributor checklist, an LLM check tool, an adversarial exploit agent, and ~3 reviewer-hours per task. — [arXiv 2601.11868](https://ar5iv.labs.arxiv.org/html/2601.11868)
- **BetterBench (NeurIPS 2024 D&B) offers 46 lifecycle criteria** and found implementation weakest across 24 benchmarks (17/24 lacked a results-replicating script; 14/24 reported no multi-run variance), publishing a minimum-QA checklist. — [arXiv 2411.12990](https://ar5iv.labs.arxiv.org/html/2411.12990v1), [betterbench.stanford.edu](https://betterbench.stanford.edu)
- **Framework-level precedent:** the UK AI Safety Institute's `inspect_evals` merged an SWE-bench **oracle solver** into the harness (v0.14.2), and HELM unit-tests that rendered instances carry the `reference [correct]` label. — [inspect_evals PR #1833](https://github.com/UKGovernmentBEIS/inspect_evals/pull/1833), [HELM test_scenario.py](https://raw.githubusercontent.com/stanford-crfm/helm/main/src/helm/benchmark/scenarios/test_scenario.py)

## NOT FOUND (explicitly flagged)

- **No universal mandate.** No venue, funder, or standards body I could find requires evaluator/grader validation as a condition of publication or leaderboard entry. The NeurIPS Paper Checklist has reproducibility, code, statistical-significance, and asset items but **no item requiring validation of the evaluator/harness itself**; I could not parse the ML Reproducibility Checklist PDF, so its items are unverified. — [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)
- **"AI Agent Benchmark Cookbook"** — no publication, arXiv entry, or lab/HuggingFace artifact found under that title; do not cite it. **Verifier validation as a named research method** ("score gold = 1, no-op = 0") — not found; the nearest equivalents are ABC T.9, Vally's `--no-golden-input`, and Inspect's oracle solver. — [inspect_evals PR #1833](https://github.com/UKGovernmentBEIS/inspect_evals/pull/1833)
- **MLCommons** — no fetched source stating a "run the reference solution through the harness" rule. **EvalBiasBench** — no paper by that name surfaced. **"When Large Language Model Agents Meet Sycophancy"** — not located. **RewardBench** exists (arXiv 2403.13787) but I did not fetch numeric accuracy. — [arXiv 2403.13787](https://arxiv.org/abs/2403.13787)

# Trajectory Representation for LLM-Agent Experience/Skill Extraction
### What is kept and what is dropped when a raw agent trajectory is fed to an LLM that extracts reusable knowledge

**Scope:** 2023–2026, primary sources = arXiv full texts + official repos (prompt files read directly) + vendor engineering docs.
**Method note:** where a system's prompt templates are figures (not extractable text), I read the released code instead. Line-level quotes below are verbatim from the files cited.

---

## 1. What exactly is serialized into the extraction prompt in named systems

### 1.1 ExpeL (arXiv 2308.10144, AAAI-24) — raw ReAct text, **not** (obs, action, reward) tuples

1. **ExpeL's insight-extraction call receives the raw trajectory *string*.** The code sets `success_history = traj.trajectory.strip()` and `fail_history.trajectory.strip()`, then passes those strings straight into `prompt_critique(...)`. The `Trajectory` object stores the trajectory as a single opaque string (`self._trajectory = trajectory`) and only *derives* `observations` / `actions` / `thoughts` lists by splitting that string for embedding/retrieval metadata — the extraction prompt uses the unsplit string. Source: [`agent/expel.py` L133–139, L343–352](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/expel.py), [`memory/episode.py`](https://github.com/LeapLabTHU/ExpeL/blob/main/memory/episode.py) ([ExpeL, 2023/2024](https://arxiv.org/abs/2308.10144)).
2. **So the serialized form is the agent's own interleaved ReAct text** — `Thought:` / `Action:` / `Observation:` lines produced by the base ReAct agent — for both the successful and the failed trial. There is no explicit `(observation, action, reward)` tuple encoder and no reward scalar in the prompt; the pair is selected by *outcome* (success vs. fail for the same task) rather than by reward value (["Learning from Successes and Failures"](https://arxiv.org/abs/2308.10144)).
3. **Thoughts are kept, not truncated by default.** `truncate_strategy: null` is the shipped default in [`configs/agent/expel.yaml`](https://github.com/LeapLabTHU/ExpeL/blob/main/configs/agent/expel.yaml), and the insight prompt asks the model to critique "how to perform better **Thought and Action**" ([`prompts/templates/human.py`](https://github.com/LeapLabTHU/ExpeL/blob/main/prompts/templates/human.py)).
4. **There IS one hard token-driven truncation, and it only applies to the failure side.** In `failure_critique()`: `if self.token_counter(failed_trials) > 13000:` → prints `TRUNCATING FAILED TRIALS` and **drops exactly one failed trajectory**, chosen by `critique_truncate_strategy` = `random` (default) / `longest` / `shortest`. Source: [`agent/expel.py` L173–192](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/expel.py), default in [`configs/agent/expel.yaml`](https://github.com/LeapLabTHU/ExpeL/blob/main/configs/agent/expel.yaml).
5. **How many trajectories per extraction call:** successes are chunked by `random_divide_list(all_success, self.success_critique_num)` with `success_critique_num: 8` — i.e. up to **8 successful trajectories concatenated** as `task + '\n' + trajectory` into one "all-success" critique prompt. Compare-pair critiques are strictly 1 success + 1 failure. Source: [`agent/expel.py` L152–171](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/expel.py).
6. **Ablation on the extraction input mix (from the paper, Table 3 analysis):** "using reflections in addition to success/failure pairs and lists of successes is **disadvantageous**, possibly due to reflections sometimes outputting hallucinations." Learned insights beat hand-crafted insights; `gpt-4` extraction beats `gpt-3.5-turbo` ([ExpeL, 2023](https://arxiv.org/abs/2308.10144)).
7. **Context limits during *acting* (not extraction):** the base agent declares itself truncated when `token_counter(log_history) > 15800`, and HotpotQA runs use `max_steps: 7`, `num_fewshots: 6`, retrieval `k = num_fewshots × buffer_retrieve_ratio` = 6 × 4 = **24 candidates**, then filters out any fewshot whose token count exceeds `max_fewshot_tokens` (default `auto`) and takes 6. Source: [`agent/base.py` L34–35](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/base.py), [`configs/benchmark/hotpotqa.yaml`](https://github.com/LeapLabTHU/ExpeL/blob/main/configs/benchmark/hotpotqa.yaml), [`agent/expel.py` L531–568](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/expel.py).
8. **Insight block budget:** `max_num_rules: 20`, with a soft cap at `max_num_rules + 5` (=25) before the prompt switches to the "full" variant that says *"Focus on REMOVE rules first, and stop ADD rule unless the new rule is VERY insightful"* ([`configs/agent/expel.yaml`](https://github.com/LeapLabTHU/ExpeL/blob/main/configs/agent/expel.yaml), [`prompts/templates/human.py`](https://github.com/LeapLabTHU/ExpeL/blob/main/prompts/templates/human.py)).
   - **NOT FOUND:** what `max_fewshot_tokens: auto` resolves to numerically.
   - **NOT FOUND:** the literal prompt text of ExpeL's Figure 2/3 templates (they are images in the PDF/HTML; no public prompt file reproduces them 1:1 — the `.py` files contain the wrapper templates only).

### 1.2 AutoGuide (arXiv 2403.08978) — trajectory = `(x₀,a₀,r₀,…,r_T)`; contrast on the **divergence timestep**, context summarized over the shared prefix

9. **Formal trajectory definition:** "Each trajectory **τ = (x₀,a₀,r₀,…,r_T)** is a sequence of observations, actions, and rewards following the partially observable Markov decision process" — so observation, action *and* reward are all present in the object, unlike ExpeL ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), §3.1).
10. **The contrastive pair construction is the key "what is kept" decision.** Given `τ⁺` and `τ⁻` for the same task with `R(τ⁺) > R(τ⁻)`: "we compare these two trajectories to find the **deviation timestep** `t` at which they begin to diverge due to different actions. Then we apply the context identification module to **summarize the context for the shared part of the trajectory** `τ_{:t}`." Only then is the guideline extracted from both full trajectories *with respect to that context*. Worked example: context = `On the Reddit main page`; guideline = *"When on the Reddit main page, if you want to navigate to a specific forum, you should click on 'link Forums' located right above 'link Wiki'"* ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), §3.2, Fig. 2).
11. **The trajectory is compressed to a context string at extraction time**, and at inference it is compressed again: the test-time agent identifies the context of `τ`, and `M_select(context, τ; G, k)` picks the top-k guidelines ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), §3.3).
12. **AutoGuide's own argument that raw trajectories don't fit:** "ReAct with **more than 6 shots often exceeds the token limit of GPT-3.5-turbo**… directly inputting raw trajectories into ReAct for in-context learning is **not** an effective way to fully leverage offline data" ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), §4.3 Q4).
13. **WebShop hyperparameters (Table 8):** allowed episode length 15; # search results 3; n-shots 1; **top-k guideline selection = 2**; guideline-extraction model `gpt-4-1106-preview`; context-ID and selection models `gpt-3.5-turbo-0613`; 50 training tasks ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), Appendix B.2.3).
    - **NOT FOUND:** exact prompt strings — Appendix C.1–C.4 templates are figures (`Figures 5–11`) with no released repo (no public `AutoGuide` repo found under the author/org names searched).

### 1.3 Agent Workflow Memory (arXiv 2409.07429) — reasoning **is kept**; in WebArena the observation is **dropped entirely**

14. **The published workflow step is a triple**, verbatim: "Each [step] consists of three parts… **(1) A description of the current environment state in NL**, such as 'Order {id} is shown'; **(2) The reasoning process elaborated by the agent** to decide which action to generate based on observations…; and **(3) an action represented as an executable program** over the environment, i.e. `stop()`" ([AWM, 2024](https://arxiv.org/abs/2409.07429), §2.2).
15. **But the *induction input* differs by benchmark, and the difference is exactly the observation channel:**
    - **WebArena:** `format_trajectory()` emits, per step, `<think>\n{think}\n</think>\n<action>\n{acts}\n</action>` — **reasoning is preserved verbatim; the observation/AxTree is never serialized into the prompt.** Source: [`webarena/induce_prompt.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/webarena/induce_prompt.py); example artifacts in [`webarena/workflow/shopping.txt`](https://github.com/zorazrw/agent-workflow-memory/blob/main/webarena/workflow/shopping.txt).
    - **Mind2Web:** `format_examples()` emits only `Query #i: {confirmed_task}` + `Actions and Environments:` + `ex["action_reprs"]` lines, where each repr is `[tag] element description -> CLICK/TYPE: value`. The "environment" is therefore reduced to the *single target element's accessibility label*, not the page. Source: [`mind2web/utils/data.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/utils/data.py), [`mind2web/one_shot_abstract.txt`](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/prompt/one_shot_abstract.txt).
16. **Steps are dropped before induction.** In WebArena, `remove_invalid_steps()` deletes `scroll(...)` and `noop(...)` actions and any `click`/`fill` whose arguments don't parse as `(str, int)` / `(str, str)` ([`webarena/induce_prompt.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/webarena/induce_prompt.py)).
17. **Induction input selection:** deduplicate trajectories by `intent_template_id`, then `random_group_sample(template_dict, args.num_samples)` with **`num_samples: 1` (default) — max one sample per task template** is fed to the induction prompt ([`webarena/induce_prompt.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/webarena/induce_prompt.py)).
18. **Retrieval budget:** induced workflows are injected as a single user message, plus `random.sample(concrete_examples, min(args.retrieve_top_k, len(concrete_examples)))` concrete exemplars from `exemplars.json` ([`mind2web/memory.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/memory.py)).
19. **At acting time the observation is aggressively pre-filtered:** `get_top_k_obs(s, top_k)` keeps the 1 positive candidate + `top_k − 1` highest-ranked negative candidates from the *cleaned HTML*, and the acting prompt keeps only `previous_k = 5` prior (observation, action) pairs ([`mind2web/utils/env.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/utils/env.py), [`mind2web/memory.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/memory.py)).
20. **AWM's own ablation of "summarize the observation" vs "keep HTML" (Table 8, Mind2Web, GPT-3.5):**
    | NL state desc. | filtered HTML | Elem Acc | Action F1 | Step SR | SR |
    |---|---|---|---|---|---|
    | ✓ | ✗ | 39.0 | 52.8 | 34.6 | **2.8** |
    | ✗ | ✓ | 38.1 | 54.0 | 33.8 | 2.8 |
    | ✓ | ✓ | 37.1 | 51.3 | 32.9 | **2.0** |
    Conclusion verbatim: "**NL description of states is more useful than HTML**… Interestingly, using both NL and filtered HTML leads to **worse** results… the filtered HTML has a substantial number of irrelevant items (**missing all correct elements 47% of the time**) thus potentially contradicting NL descriptions" ([AWM, 2024](https://arxiv.org/abs/2409.07429), §4.3). This is the single cleanest published ablation of *observation representation* inside an extracted-skill artifact.
21. **Code vs. text action representation (Table 7, Mind2Web):** AWM (code) 50.6 / 57.3 / 45.1 / **4.8** vs. AWM-text 51.2 / 57.4 / 45.4 / **3.6** — "we do not find substantial performance variance… both forms can bring effective augmentations" ([AWM, 2024](https://arxiv.org/abs/2409.07429), §4.2).
22. **Abstract sub-routine vs. full concrete example (Table 6):** MindAct 41.6/60.6/36.2/**2.0**; AWM_rule 49.5/57.0/43.4/2.0; **AWM_lm 50.6/57.3/45.1/4.8** — "abstract representation of example-specific contexts… introduces less bias on element selection" ([AWM, 2024](https://arxiv.org/abs/2409.07429), §4.1).

### 1.4 Reflexion (arXiv 2303.11366) — reflection memory is a **last-3 sliding window**; the *full* trial log is fed to the reflector

23. **The reflection-memory window is hard-coded to 3.** In `update_memory()`: `if len(env['memory']) > 3: memory = env['memory'][-3:] else: memory = env['memory']`. The reflection prompt then appends `Plans from past attempts:\nTrial #{i}: {m}` for each retained plan ([`alfworld_runs/generate_reflections.py`](https://github.com/noahshinn/reflexion/blob/main/alfworld_runs/generate_reflections.py)).
24. **The "memory" buffer is a list of free-text reflection strings, not tuples** — `env_configs[i]['memory'] += [reflection]` ([`alfworld_runs/generate_reflections.py`](https://github.com/noahshinn/reflexion/blob/main/alfworld_runs/generate_reflections.py)). The paper describes it as "an episodic memory buffer" of "reflective text" ([Reflexion, 2023](https://arxiv.org/abs/2303.11366)).
25. **The input to the reflector is the raw rollout log, deliberately un-summarized:** `_get_scenario(log_str)` slices everything after `"Here is the task:"` and the prompt instructs: *"You will be given the history of a past experience… **Do not summarize your environment**, but rather think about the strategy and path you took… Devise a concise, new plan of action that accounts for your mistake with reference to specific actions that you should have taken."* ([`alfworld_runs/generate_reflections.py`](https://github.com/noahshinn/reflexion/blob/main/alfworld_runs/generate_reflections.py), quoted verbatim).
26. **Extraction only happens on failure:** `if not env['is_success'] and not env['skip']:` ([`alfworld_runs/generate_reflections.py`](https://github.com/noahshinn/reflexion/blob/main/alfworld_runs/generate_reflections.py)).
    - **NOT FOUND:** a paper-stated token cap of "1/3/5 reflections" as a *token* budget. The code shows a count-based window of 3; I could not locate a token-denominated cap or a published 1/3/5 ablation table in the v4 HTML. Treat "1/3/5 reflections" as unverified.

### 1.5 Voyager (arXiv 2305.16291) — stores **code** + a ≤6-sentence description; raw execution errors go back verbatim

27. **The skill artifact = executable JS code + an LLM-written description, stored as separate files.** `self.skills[program_name] = {"code": program_code, "description": skill_description}`; files are written to `skill/code/{name}.js` and `skill/description/{name}.txt`. The description prompt (`voyager/prompts/skill.txt`) says verbatim: *"Try to summarize the function in **no more than 6 sentences**… Your response should be a **single line of text**."* Source: [`voyager/agents/skill.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/agents/skill.py), [`voyager/prompts/skill.txt`](https://github.com/MineDojo/Voyager/blob/main/voyager/prompts/skill.txt) ([Voyager, 2023](https://arxiv.org/abs/2305.16291)).
28. **What is retrieved is the *code*, keyed by the *description*:** the description text is embedded in Chroma; `retrieve_skills` returns `self.skills[name]["code"]` for the top-k. **`retrieval_top_k` default = 5** ([`voyager/agents/skill.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/agents/skill.py), [`voyager/voyager.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/voyager.py) L44–46).
29. **Raw environment feedback is fed back for repair, and it is *not* truncated in the code path I traced.** `render_human_message` builds `error = "\n".join(error_messages)` and emits `Execution error:\n{error}` verbatim; the source handler `onError.js` simply stores and returns the raw error object (`this.obs = err; … return result`) with **no `split`/`slice`/line cap**. Source: [`voyager/agents/action.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/agents/action.py), [`voyager/env/mineflayer/lib/observation/onError.js`](https://github.com/MineDojo/Voyager/blob/main/voyager/env/mineflayer/lib/observation/onError.js).
    - **NOT FOUND:** any "first N lines" truncation of error messages. I checked the error path end-to-end; there is none. The prompt template declines a fixed field list (`action_template.txt`) but that is a schema, not a truncation.
30. **Retry/iteration budget:** `action_agent_task_max_retries: int = 4`; the human message template itself declares the fields the LLM will receive each repair round: `Code from the last round`, `Execution error`, `Chat log`, `Biome`, `Time`, `Nearby blocks`, `Nearby entities`, `Health`, `Hunger`, `Position`, `Equipment`, `Inventory (xx/36)`, `Chests`, `Task`, `Context`, `Critique` ([`voyager/agents/action.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/agents/action.py), [`voyager/prompts/action_template.txt`](https://github.com/MineDojo/Voyager/blob/main/voyager/prompts/action_template.txt)).
31. **Chat log *is* selectively filtered** even though error text is not: `summarize_chatlog()` keeps only messages matching craft/mine-failure regexes (`"I cannot make X because I need: …"`, `"I need at least a X to mine …!"`) and collapses them to `"I also need <item>, <item>."` ([`voyager/agents/action.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/agents/action.py)).
32. **Critic input is a *state snapshot*, not the trajectory:** the critic prompt receives post-execution `Biome / Nearby blocks / Health / Hunger / Position / Equipment / Inventory / Chests / Task / Context` and returns JSON `{reasoning, success, critique}` ([`voyager/prompts/critic.txt`](https://github.com/MineDojo/Voyager/blob/main/voyager/prompts/critic.txt)).

### 1.6 2025–2026: systems that explicitly restructure the trajectory before extraction

33. **Skill-Evo4GUI / "From Interaction Traces to Persistent Skills" (arXiv 2609.04869, 2026)** has the most explicit *serialization contract* I found. Its `Extractor` agent reads "a complete rollout record and produce[s] an objective, structured summary," with the preservation rule stated verbatim: **"`step_level_record`: include EVERY step without selective omission."** Each step is forced into four fields: `step`, `observed_state` ("observable UI state before the action"), `action_taken`, `post_action_effect` ("observable effect immediately after the action"), `notes`. The extractor is explicitly forbidden to judge: *"State facts only; do not make judgments… Do not evaluate or reference any skill library."* Screenshots are **dropped by default** — `evidence_coverage.visual_mode` ∈ `{none, selected_delivered_skill_screenshots}` with `selected_steps`/`image_count`. Source: [`Extractor.md`](https://github.com/LongtaoHu/Skill-Evo4GUI/blob/main/Extractor.md) ([Hu et al., 2026](https://arxiv.org/abs/2609.04869)).
34. **Skill-Evo4GUI separates "extract facts" from "propose edits"** across three prompts (`Extractor.md` → structured facts → `Proposer.md` → create/edit/delete/preserve → `skill_builder.md` → full `SKILL.md`), i.e. the trajectory is *never* shown directly to the skill author. Reported effect: after a five-iteration empty-library warm-up, the full evolving-library system beats a configuration-matched empty-library control in all four OSWorld domain runs, **+5.7 to +18.6 percentage points** mean evaluator score ([Hu et al., 2026](https://arxiv.org/abs/2609.04869)).
35. **SkillTTA / "Skills on the Fly" (arXiv 2605.16986, 2026)** retrieves "task-relevant **training trajectories**" and synthesizes a *temporary* skill conditioned on the target context — i.e. extraction is deferred to inference and conditioned on the current state, rather than being a one-shot compression of a stored trace ([Wang et al., 2026](https://arxiv.org/abs/2605.16986)).
36. **Trace2Tower (arXiv 2609.05261, 2026)** drops raw steps to a canonical vocabulary first: "Trace2Tower **abstracts step-level interactions into canonical events**, constructing a unified graph governed by semantic compatibility, transition dynamics, and outcome evidence," then isolates "stable, success-aligned behavioral modes" via contrastive spectral decomposition, populating a tower of action templates → procedural routines → task strategies. Reported: **87.31%** success / **10.35** steps / **0.26** invalid actions on ALFWorld; **50.67%** exact success on WebShop ([Sun et al., 2026](https://arxiv.org/abs/2609.05261)).
37. **Trace2Skill (arXiv 2603.25158, 2026)** "consolidates broad execution trajectories **in parallel** into a unified skill directory through inductive reasoning," explicitly positioned *against* retrieval memory: it "outperforms sequential skill editing and **ReasoningBank-style retrieval memories**," and evolved skills transfer across model scales (Qwen3.5-35B trajectories → Qwen3.5-122B agent **+57.65 pp** on WikiTableQuestions) ([Ni et al., 2026](https://arxiv.org/abs/2603.25158)).
38. **SkillRL (arXiv 2602.08234, ICLR 2026)** states the raw-vs-distilled contrast as its motivation verbatim: *"Existing memory-based methods primarily store **raw trajectories, which are often redundant and noise-heavy**. This prevents agents from extracting high-level, reusable behavioral patterns…"* Its fix is "experience-based distillation… to build a hierarchical skill library SkillBank," reported to "significantly reduce the token footprint" and beat strong baselines "over 15.3%" ([Xia et al., 2026](https://arxiv.org/abs/2602.08234)).
39. **The 2026 survey "Experience Compression Spectrum" (arXiv 2604.15877) formalizes the design space** as Levels 0→3 (raw trace 1:1 → episodic memory 5–20× → procedural skill 50–500× → declarative rule 1,000×+) and maps 20+ systems onto it, including ExpeL and AutoGuide as the only "cross-level" systems. Source: ([Zhang et al., 2026](https://arxiv.org/abs/2604.15877)).

## 2. Concrete token budgets and context-window compression strategies

40. **ExpeL:** insight list capped at `max_num_rules: 20` (soft 25 with a "stop ADDing" instruction); **8 successes per extraction chunk**; failure-side trajectory set truncated when `> 13,000` tokens by dropping one trajectory; acting-time truncation trigger at `15,800` tokens; 7 max steps and 6 fewshots (HotpotQA); retrieval over `6 × 4 = 24` candidates filtered by a per-fewshot token cap. Sources: [`configs/agent/expel.yaml`](https://github.com/LeapLabTHU/ExpeL/blob/main/configs/agent/expel.yaml), [`agent/expel.py`](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/expel.py), [`agent/base.py`](https://github.com/LeapLabTHU/ExpeL/blob/main/agent/base.py), [`configs/benchmark/hotpotqa.yaml`](https://github.com/LeapLabTHU/ExpeL/blob/main/configs/benchmark/hotpotqa.yaml).
41. **Reflexion:** sliding window of **3** reflections; each reflection is unbounded free text (the paper's stated benefit is that reflections are short, not that they are capped) ([`generate_reflections.py`](https://github.com/noahshinn/reflexion/blob/main/alfworld_runs/generate_reflections.py)).
42. **Voyager:** retrieval **top-5** skills; description constrained to **≤6 sentences, single line**; per-task retry budget **4**; **full code** of retrieved skills is injected, not the descriptions ([`voyager/agents/skill.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/agents/skill.py), [`voyager/voyager.py`](https://github.com/MineDojo/Voyager/blob/main/voyager/voyager.py), [`voyager/prompts/skill.txt`](https://github.com/MineDojo/Voyager/blob/main/voyager/prompts/skill.txt)).
43. **AutoGuide:** **top-k = 2** guidelines selected per state, from ~50 collected training tasks, episode length 15; the "knowledge block" is a set of one-line conditional sentences, so the budget is per-guideline text length, not a global token cap ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), Tables 4 & 8).
44. **AWM:** all workflow induction runs on **1 sample per task template**; at acting time the observation is pruned to the top-k candidate HTML elements and only the **last 5** (observation, action) pairs are kept; workflows are grouped **per website** to keep each collection small ([`induce_prompt.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/webarena/induce_prompt.py), [`memory.py`](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/memory.py), [AWM, 2024](https://arxiv.org/abs/2409.07429) §3).
45. **SWE-agent (arXiv 2405.15793) — the canonical "budget by structure, not by summarization" design:**
    - file viewer window = **at most 100 lines**; `scroll_down`/`scroll_up` move exactly 100 lines; the header always shows full path, total lines, lines omitted before/after;
    - search commands return **at most 50 results**; if exceeded, **no results are shown** and the agent is told to write a more specific query;
    - **"observations preceding the last 5 are each collapsed into a single line"** — a placeholder of the form `Old output omitted (101 lines)`;
    - **"all past error messages except the first are omitted"**;
    - the system prompt is never collapsed.
    Sources: ([Yang et al., 2024](https://arxiv.org/abs/2405.15793), §3 and Appendix A; ablations in Table 3).
46. **SWE-agent ablation of the budget itself (Table 3, SWE-bench Lite, GPT-4 Turbo, % resolved):** File viewer **30 lines → 14.3** (−3.7), **100 lines → 18.0**, **full file → 12.7** (−5.3); Search **summarized → 18.0**, **iterative/verbose → 12.0** (−6.0); Context management **last-5-obs → 18.0** vs **full history → 15.0** (−3.0); edit-with-linting **18.0** vs edit action 15.0. Reading *more* of the same file is worse than the 100-line window ([Yang et al., 2024](https://arxiv.org/abs/2405.15793)).
47. **"The Complexity Trap" (arXiv 2508.21433, NeurIPS'25 DL4C workshop)** gives the operational note that matters for replication: the rolling window is an **agent-specific hyperparameter**. On OpenHands, re-using SWE-agent's optimal window "degrades drastically"; after tuning, results reproduce. Concrete config used: `LLM-Summary N=21, M=10`; `Observation Masking M=10` and `M=58`; turn limit 250; 50-instance SWE-bench Verified slice with Gemini 2.5 Flash ([Lindenbauer et al., 2025](https://arxiv.org/abs/2508.21433), §5.1).
48. **Claude Code (vendor docs) — the most explicitly quantified production budget set:**
    - auto memory `MEMORY.md`: **first 200 lines or 25 KB, whichever comes first**, loaded every session; content past the limit is *not* loaded (an over-limit write still succeeds but returns an error);
    - `CLAUDE.md`: target **<200 lines**; files **>4 MiB are skipped entirely**;
    - after `/compact`: **re-reads up to 5 most recently modified files**; a file **>5,000 tokens** comes back as a path reference (`Referenced file`) with no content; invoked skill bodies re-injected **capped at 5,000 tokens per skill and 25,000 tokens total, oldest dropped first**;
    - hook/tool output **over 10,000 characters** is written to a file and Claude receives "a preview and the file path instead";
    - MCP tool **schemas are deferred by default** (`ENABLE_TOOL_SEARCH=auto` loads them only if they fit within **10% of the context window**).
    Sources: ([Claude Code docs — memory](https://code.claude.com/docs/en/memory), [context window](https://code.claude.com/docs/en/context-window)).
49. **What Claude Code's compaction keeps vs. drops is stated verbatim:** the compacted block "keeps: your requests and intent, key technical concepts, files examined or modified with important code snippets, **errors and how they were fixed**, pending tasks, and current work. It replaces the verbatim conversation: **full tool outputs and intermediate reasoning are gone.**" In the doc's own simulation the summary block is sized at **12% of the summarized tokens** ([Claude Code docs — context window](https://code.claude.com/docs/en/context-window); the 0.12 factor is in the page's simulation code, so treat it as illustrative rather than a measured production ratio).
50. **OpenHands** ships `LLMSummarizingCondenser` as the default: it triggers when history exceeds a configured size limit, "keeps recent messages intact," "preserves key information (user goals, technical specifications, critical files)," and summarizes older content; a `PipelineCondenser` composes several condensers ([OpenHands — Condenser](https://docs.openhands.dev/sdk/arch/condenser), [Context Condenser guide](https://docs.openhands.dev/sdk/guides/context-condenser)).
51. **Web-agent observation filtering has its own 2025–2026 line of evidence:**
    - **FocusAgent (arXiv 2510.03204, TMLR 08/2026):** a lightweight LLM retriever extracts the most relevant **lines from the accessibility tree (AxTree)** guided by the task goal; **matches strong baselines while reducing observation size by over 50%**, and a variant significantly reduces prompt-injection attack success ([Kerboua et al., 2025/2026](https://arxiv.org/abs/2510.03204)).
    - **"Revisiting Observation Reduction" (arXiv 2605.29397, 2026)** introduces the **Minimal Failure Set (MFS)** — "the minimal set of HTML elements whose removal causes task failure" — and defines **coverage** as the fraction of instances fully retaining the MFS. Reported: an MFS-optimized pruning program gives **2.2× faster per-step latency on WorkArena L1 while retaining 84% of original success**, and **3.1× faster on WebLinx retaining 89%**; end-to-end evaluation of 11 methods × 32 configs × 33 tasks took **232.4 cumulative hours**, which is why they needed the proxy ([Enomoto et al., 2026](https://arxiv.org/abs/2605.29397)).
52. **AgentCore Memory (AWS) separates raw from derived explicitly:** short-term memory "stores **raw interactions**… the entire conversation history as a series of events"; long-term memory "stores **structured information extracted from raw agent interactions**… preserves only the key insights such as summaries of the conversations, facts and knowledge, or user preferences," produced by an async **Extraction → Consolidation** pipeline and retrieved via semantic search over memory records ([AgentCore Memory types](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-types.html)).
53. **AgentCore's episodic strategy defines the extracted schema:** it "captures interactions as structured episodes consisting of **scenarios, intents, thoughts, actions taken, outcomes, and artifacts**," with a second derivation layer of **reflections** built across episodes. Output is XML; "each episode is broken down into a **situation, intent, assessment, justification, and episode-level reflection**," and "the episode is analyzed **turn-by-turn**." Records are indexed on **"intent" for episodes and "use case" for reflection**. Critically for Q4: the docs advise that "when creating short-term memories with `CreateEvent`, **including `TOOL` results will yield optimal results**" ([AgentCore episodic memory strategy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/episodic-memory-strategy.html)).

## 3. Measured effect of trajectory compression/summarization on downstream quality

54. **The single closest thing to "raw vs summarized" for an agent's *context* (not skills) is The Complexity Trap (arXiv 2508.21433).** SWE-agent on SWE-bench Verified, five model configs, Table (solve rate %, instance cost $):
    | Model | Strategy | Solve Rate | Cost |
    |---|---|---|---|
    | Qwen3-32B | Raw Agent | 17.0 | 1.12 |
    | | Observation Masking | 15.0 (−11.8%) | **0.55 (−50.9%)** |
    | | LLM-Summary | 16.0 (−5.9%) | 0.50 (−55.4%) |
    | Qwen3-32B (thinking) | Raw | 23.0 | 0.51 |
    | | Observation Masking | **24.6 (+7.0%)** | 0.46 (−9.8%) |
    | | LLM-Summary | **24.8 (+7.3%)** | 0.51 (0.0%) |
    | Qwen3-Coder 480B | Raw | 53.4 | 1.29 |
    | | Observation Masking | **54.8 (+2.6%)** | **0.61 (−52.7%)** |
    | | LLM-Summary | 53.x | — |
    Headline: "Observation Masking is not only **52% cheaper** than the Raw Agent baseline but also **improves the solve rate by 2.6%**… even reduces the cost per instance compared to LLM-Summary by **$0.03 ($15 across 500 instances)**." A hybrid masking+summary variant cuts a further **7% vs masking and 11% vs summary**. The paper also reports a "**Trajectory Elongation Effect**": summarization makes trajectories longer. Source: ([Lindenbauer et al., 2025](https://arxiv.org/abs/2508.21433), §4–5). **Caveat:** this measures *acting* context management, not skill-extraction quality.
55. **AgentDiet (arXiv 2509.23586, FSE 2026)** removes "useless, redundant, and expired" information from coding-agent trajectories at inference time: **39.9%–59.7% input-token reduction** and **21.1%–35.9% total cost reduction** "while maintaining the same agent performance," across two LLMs and two benchmarks ([Xiao et al., 2025/2026](https://arxiv.org/abs/2509.23586)).
56. **DPM / "Stateless Decision Memory for Enterprise AI Agents" (arXiv 2604.20158, 2026)** is the cleanest head-to-head of **summarization-based memory vs. a log-plus-single-projection** at matched budgets. Setup: mean trajectory **26,762 characters**; three character budgets — tight **1,338** (20.0×), moderate **5,352** (5.0×), loose **13,381** (2.0×); backend `claude-haiku-4-5-20251001`, temperature 0, n=10 cases, paired permutation tests. Results: no significant difference at moderate/loose budgets; **at 20× compression, DPM improves factual precision by +0.52 (Cohen's h = 1.17, p = 0.0014) and reasoning coherence by +0.53 (h = 1.13, p = 0.0034)**; DPM is **7–15× faster** (one LLM call at decision time vs. N); audit surface 2 LLM calls vs **83–97** for summarization on LongHorizon-Bench. Verbatim on what summarization loses: "both conditions inherit residual API-level nondeterminism, but the architectural asymmetry is systemic: DPM exposes **one** nondeterministic projection call, summarization-based memory exposes **N compounding** calls." ([Srinivasan, 2026](https://arxiv.org/abs/2604.20158)).
57. **The Experience Compression Spectrum paper's summary table of compression deltas** (Table 2; note the authors warn rows span different benchmarks and are not directly comparable):
    | Study | Comparison | Benchmark | Δ |
    |---|---|---|---|
    | SkillRL | L2 skill vs. L1 trajectory retrieval | ALFWorld | **+68.5 pp** |
    | Trace2Skill | L2 vs. human-written skill | SpreadsheetBench | **+21.5 pp** |
    | Trace2Skill | L2 vs. no skill | SpreadsheetBench | **+42.1 pp** |
    | SkillsBench | curated L2 vs. none | multi-task | **+16.2 pp** |
    | SkillsBench | **self-generated** L2 vs. none | multi-task | **+0.0 pp** |
    | EvoSkill | L2 vs. no skill | BrowseComp | **+5.3%** |
    | RuleShaping | L3 constraints vs. 0-shot | SWE-bench | **+7 to +14 pp** |
    Source: ([Zhang et al., 2026](https://arxiv.org/abs/2604.15877)). The `+0.0 pp` row is the important negative result: "**compression level alone is insufficient; the fidelity of the compression process determines whether the artifact is useful or merely compact noise.**"
58. **The same survey states the meta-finding directly:** "**A controlled experiment holding source experience constant while varying only compression level has not been conducted**, but existing evidence is consistent" ([Zhang et al., 2026](https://arxiv.org/abs/2604.15877), §3.3). This is the strongest available statement that sub-question 3 is *not yet properly answered in the literature*.
59. **AutoGuide's implicit raw-vs-distilled comparison (WebShop, success rate):** ReAct 1-shot 30%, 2-shot 35%, 4-shot 37%, 6-shot 38% (and >6 shots exceeds the GPT-3.5-turbo token limit) vs. **AutoGuide 46%** using guidelines distilled from the same offline data ([AutoGuide, 2024](https://arxiv.org/abs/2403.08978), Table 3). Ablating the guideline count: **k=0 → 30%, k=1 → 42%, k=2 → 46%, k=3 → 47%, k=5 → 43%** (Table 4) — i.e. too few or too many extracted artifacts both hurt.
60. **AWM's representation ablations (repeated from §1 for the effect number):** NL state description **2.8%** SR vs. filtered HTML **2.8%** vs. both **2.0%** on Mind2Web cross-task; abstract LM workflows **4.8%** SR vs. rule-induced full examples **2.0%** ([AWM, 2024](https://arxiv.org/abs/2409.07429), Tables 6 & 8).
61. **Skill-Evo4GUI's online-evolution ablation:** full evolving library vs. configuration-matched empty-library control, **+5.7 to +18.6 pp** mean evaluator score across four OSWorld domains after a five-iteration warm-up — but the paper also documents "**revision churn**, where repeated accepted edits fail to recover the originating task," i.e. compression-by-iteration is not monotonically improving ([Hu et al., 2026](https://arxiv.org/abs/2609.04869)).

## 4. Are raw tool-call outputs (command + stdout) preserved or summarized in agent memory?

### 4.1 Coding agents: aggressive, structured discarding

62. **SWE-agent (arXiv 2405.15793) summarizes stdout by *replacement*, not paraphrase.** Old observations keep their position and role in the history but their content is "replaced with a one-line placeholder… 'Old output omitted (101 lines)'." All error messages except the first are omitted. If a command produces no output, the agent gets a synthetic line: *"Your command ran successfully and did not produce any output."* Source: ([Yang et al., 2024](https://arxiv.org/abs/2405.15793), §3 "Context management" + Appendix A/Figures 30–31).
63. **The exact tool-output retention budget in SWE-agent is: last 5 observations verbatim, everything older = a line count.** Ablation at full history costs **−3.0 points** (18.0 → 15.0) ([Yang et al., 2024](https://arxiv.org/abs/2405.15793), Table 3).
64. **SWE-agent keeps editing feedback *derived from* tooling rather than the raw tool stream:** a code linter is integrated into `edit`, "Select errors from the linter are shown to the agent along with a snippet of the file contents before/after the error was introduced. Invalid edits are discarded." Linting is worth **+3.0 points** (15.0 → 18.0) ([Yang et al., 2024](https://arxiv.org/abs/2405.15793)).
65. **Agentless (arXiv 2407.01489) is the boundary case: it has no trajectory memory at all.** It replaces the agent loop with a fixed three-phase **localization → repair → patch validation** pipeline, "without letting the LLM decide future actions or operate with complex tools," reporting **32.00% (96 correct fixes) on SWE-bench Lite at $0.70** ([Xia et al., 2024](https://arxiv.org/abs/2407.01489)). Its "representation" is issue text + repository files, so the Q4 question does not apply to it — evidence that removing the trajectory entirely was competitive in 2024.
66. **OpenHands** makes the discard/summarize choice pluggable and defaults to summarize: `LLMSummarizingCondenser` keeps recent messages intact and LLM-summarizes older ones once a size threshold is crossed ([OpenHands — Condenser](https://docs.openhands.dev/sdk/arch/condenser), [guide](https://docs.openhands.dev/sdk/guides/context-condenser)). The Complexity Trap's hybrid result (mask + summarize, −7%/−11% cost) is the recommended middle path ([Lindenbauer et al., 2025](https://arxiv.org/abs/2508.21433)).

### 4.2 Production memory systems: raw stdout is generally **not** what gets persisted; a structured extraction is

67. **Claude Code explicitly drops raw tool output at compaction.** Quoted verbatim: "It replaces the verbatim conversation: **full tool outputs and intermediate reasoning are gone.**" What survives is "files examined or modified with important code snippets, **errors and how they were fixed**." Tool output over 10,000 characters is additionally offloaded to a file with only "a preview and the file path" reaching the model. Source: ([Claude Code — context window](https://code.claude.com/docs/en/context-window)).
68. **Claude Code's *auto memory* (the cross-session artifact) drops far more aggressively by design.** Verbatim: "Claude **skips anything it can derive from the codebase, such as architecture, file paths, or debugging fixes.** It also skips anything your CLAUDE.md files already say." The persisted artifact is `MEMORY.md` — **one line per memory** — as an *index* to separate topic files, and only the index's first 200 lines / 25 KB load each session; topic files load on demand. Memory is typed `user | feedback | project | reference`. Source: ([Claude Code — memory](https://code.claude.com/docs/en/memory)). Note this is a *deliberate* drop of exactly the "debugging fix" content that SWE-agent-style systems keep.
69. **Cursor's documented persistent context is author-written, not trajectory-extracted.** `cursor.com/docs/context/memories` resolves to the **Rules** page, which describes `.cursor/rules/*.mdc` (with `alwaysApply`, `globs`, `description` frontmatter) and `AGENTS.md` as "persistent, reusable context at the prompt level," and states "Large language models don't retain memory between completions." Source: ([Cursor — Rules](https://cursor.com/docs/rules)).
    - **NOT FOUND:** any Cursor documentation describing an automatic trajectory→skill/memory extraction pipeline or its serialization. The Memories URL redirects to Rules, and I could not locate an official spec for what a Cursor "Memory" contains.
70. **AgentCore's episodic memory is the clearest production spec for trajectory→knowledge extraction, and it deliberately does *not* store raw stdout.** "Instead of storing every raw event, it **identifies important moments, summarizes them into compact records**, and organizes them so the system can retrieve what matters without noise." The extracted episode schema is `situation, intent, assessment, justification, episode-level reflection` plus `scenarios, intents, thoughts, actions taken, outcomes, artifacts`; reflections add cross-episode guidance ("which tool combinations consistently lead to successful outcomes"). Retrieval is semantic. Sources: ([AgentCore episodic memory strategy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/episodic-memory-strategy.html), [memory types](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-types.html)).
71. **But AgentCore gives one strongly pro-raw-signal instruction:** "When creating short-term memories with `CreateEvent`, **including `TOOL` results will yield optimal results**," and for reuse "for similar successful episodes, **linearize the turns within the episode and feed only this to the agent** so it focuses on the main steps" ([AgentCore episodic memory strategy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/episodic-memory-strategy.html)). So: raw tool results are ingested as *evidence*, extracted into structured records, and re-linearized (not re-rawed) at reuse time.

## GAPS / NOT FOUND

- **NOT FOUND — a controlled experiment that varies *only* trajectory compression level while holding source experience constant, and measures downstream skill quality.** Stated explicitly by the 2026 survey: "A controlled experiment holding source experience constant while varying only compression level has not been conducted" ([Zhang et al., 2026](https://arxiv.org/abs/2604.15877), §3.3). All available deltas (Table 2 of that paper; SkillRL, Trace2Skill, SkillsBench, EvoSkill, RuleShaping) confound compression with system, benchmark, and model.
- **NOT FOUND — ExpeL's literal insight-extraction prompt text.** The wrappers are in `prompts/templates/human.py`, but the prompt templates shown in the paper (Figs. 2–3, 8–13) are images; no released file reproduces them verbatim.
- **NOT FOUND — what ExpeL's `max_fewshot_tokens: auto` resolves to numerically**, or a per-successful-trajectory token cap (the only trajectory-level truncation I found is the >13,000-token failure-side drop).
- **NOT FOUND — a paper-stated token cap of "1/3/5 reflections" in Reflexion.** The code hard-codes a *count* window of the last 3; I found no token-denominated cap or 1/3/5 ablation in the v4 HTML.
- **NOT FOUND — any truncation of Voyager execution errors (e.g. "first N lines").** I traced `onError.js → events → render_human_message`; the error is joined and emitted verbatim. (Chat logs, by contrast, *are* selectively filtered via `summarize_chatlog`.)
- **NOT FOUND — AutoGuide prompt template text.** Appendix C.1–C.4 are figures (Figs. 5–11); no public AutoGuide repository was found under the author/org names I searched.
- **NOT FOUND — Cursor's memory serialization.** `cursor.com/docs/context/memories` redirects to the Rules page; no official doc describing automatic trajectory→memory extraction, its schema, or its budget.
- **NOT FOUND — AgentCore's actual extraction/projection prompt.** The docs describe inputs/outputs (`memory-episodic-prompt.md` is referenced) but the extraction prompt text is not public in the pages I could retrieve.
- **NOT FOUND — an ablation isolating "summarize the trajectory, then extract" vs "feed raw trajectory to the extractor" inside a single skill-extraction system.** The nearest substitutes are (a) The Complexity Trap and AgentDiet, which ablate context management for *acting*, and (b) AWM §4.3, which ablates *observation representation inside the extracted workflow* (NL vs. filtered HTML vs. both) rather than the extraction input format.
- **Partial / weak:** Claude Code's "summary ≈ 12% of tokens" figure comes from a documentation simulation's source code, not a published measurement; do not cite it as an empirical result.
- **Not verified at source:** the arXiv ID 2604.20158 is real and resolves (title, author, date confirmed) — "Stateless Decision Memory for Enterprise AI Agents," Vasundra Srinivasan, submitted 22 Apr 2026 — but it is a single-author preprint with n=10 cases and an LLM judge; its numbers should be treated as provisional.

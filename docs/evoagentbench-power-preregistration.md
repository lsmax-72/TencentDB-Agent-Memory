# EvoAgentBench 功效预注册（Phase 4）

状态：**预注册（执行前冻结）**。本文件只包含零模型成本的推算与已冻结证据的读数，不包含任何新的评测结论。

## 1. 为什么必须先做功效规划

迁移收益是**配对二值**结果，其检验功效取决于**不一致对（discordant pairs）**的数量，而不是标题通过率。一个基线很强的 suite 即便题目很多，只要几乎不产生不一致对，就测不出任何效应 —— 这正是前面几次 attempt 的失效模式。因此在花 token 之前，先把"这套题能否测出目标效应"算清楚。

方法：精确 McNemar 检验（单侧，α=0.05），不一致对计数由两个独立二项分布卷积得到（`scripts/evoagentbench/power.py`，仅标准库）。

## 3. 功效表（α=0.05，power=0.80，零 breaks）

| 目标净增益 | 所需配对数 n |
|---|---|
| 5pp | 134 |
| 10pp | **66** |
| 15pp | 44 |
| 20pp | 33 |

**在 n=24 时，最小可检测效应（MDE）= 26.5pp。**

这意味着：**用 24 题的 code-v2 suite，只能检测到约 26 个百分点的净增益。** 任何低于这个量级的真实效应，无论是否存在，都必然得到"不显著"—— 而 memory/skill 类资产在竞赛编程任务上的真实效应，乐观估计也在 10pp 量级。**n=24 的仪器相对于待测效应差了一个数量级。**

一致性检查：把实测噪声（2/24 双向，零送达）代入，假阳性功效为 0.001，与实际观测相符。

## 3.1 更正：更好的主指标是"严重度"，它把 MDE 减半

上表基于二值 `reward`。2026-09-14 的仪器诊断发现官方判分器**首次失败即停止**，逐条核对后确认：

- **42/42 个失败 run 满足 `total − passed == 1`**（在第一个失败用例处停止）
- **312/312 个通过 run 满足 `passed == total`**（全过）

因此 `verifier.passed` 不是"答对的用例数"，而是**"连续通过多少个用例才第一次失败"** —— 一个有序的**严重度**刻度。以 `severity = passed / 套件规模`（套件规模由该题历史全过值推断）作为配对连续主指标，功效显著更高。

**σ 是实测的**：在 v4 与 v8 的**零送达配对**上（干预一次都没送到，差值必为纯噪声）测得配对差 sd 为 **0.218（v4，20 对）** 与 **0.133（v8，15 对）**。

> 更正记录（2026-09-14）：首版曾报 σ=0.213/0.304。原因是一个**分母 bug** —— 套件规模一度取自"历史最大 `passed`"，于是**从未全过的失败题**会用自己的最好失败成绩当分母，把失败 run 算成 1.0 满分（例如 `3613` 恒为 3/3）。已改为**只有真正全过的 run 才能定义套件规模**，其余题的严重度记为未定义并单列。修正后 σ 下降，覆盖题数从 20/24 变为 19/24。

| σ | n=24 | n=44 | n=66 | 达 10pp 所需 n |
|---|---|---|---|---|
| 0.133（v8 实测） | **7.6pp** | 5.6pp | 4.6pp | **14** |
| 0.180（保守中值） | **10.3pp** | 7.6pp | 6.2pp | 26 |
| 0.218（v4 实测） | **12.5pp** | 9.2pp | 7.5pp | 38 |
| 二值对照 | 26.5pp | — | — | 66 |

**结论：同一个 24 题 suite，把主指标从二值换成严重度后，MDE 从 26.5pp 降到约 7.6–12.5pp；"检出 10pp 效应"所需题量从 66 降到 14–38 题。** 这使 Phase 4 在不扩充题量的前提下变得可行 —— 鉴于官方 train 池只剩 14 题（见 §5），这一点是必要的。

代价与注意事项：

- 严重度**同样是噪声的**。反例：v4 的 Skill 臂**送达率 0%**，严重度却是 1.00 而 vanilla 0.95 —— 与当初二值指标上那个"+8.3pp 假收益"同源。因此不能只看均值，必须保留配对检验与预注册判据。
- 严重度依赖"短路"这一判分行为；verifier 若改变，指标立即失效，所以 `exposure_audit.severity_scores` **每次都校验该不变量**（`short_circuit_invariant_holds`），不假定成立。实测该不变量在 code-v2 / code-v4 / code-v8 / positive-control-v3 上均成立。
- `total == 0`（`no_code_extracted`，从未提交）的 run 不参与严重度，单独计入 `ungraded_runs`（v8 有 6 条、v2 有 14 条、v4 有 11 条）。
- 归一化依赖"套件规模"，由历史全过值推断；从未全过的新题无法归一化，须先取得一次全过或从题面确定规模。

## 3.2 计算方式

```bash
python3 -m scripts.evoagentbench.power
```

输出同时包含二值所需题量与严重度 MDE 表。`test_power.py` 把 `required_tasks(0.10, 0.0) == 66`
与 `paired_continuous_mde(24, 0.133) == 0.076059`、`required_pairs_continuous(0.133, 0.10) == 14` 等数值**钉死**，任何统计口径（含套件规模口径）的静默改动都会让测试失败。

## 4. 退化 run 对样本量的额外要求

从不尝试题目的 run 不携带能力信号，不能算作有效配对观测。按实测退化率折算：

```
有效 n = 计划 n × (1 − 退化率)
```

按 v4 观察到的 13.9% 退化率：要拿到 66 个有效配对，需要约 **77** 个题目槽位。v9 runner-policy 协议的大预算改动**预期**降低该比率，但该预期必须由 v9 自己的 run 实测验证，不得沿用旧数字。

## 5. 硬约束：官方 train 池供不出所需的 suite

`protocol-code-v8.json` 的 `selection` 已记录：

- `official_train_count` = 182
- `excluded_prior_train_ids` = **132**（此前协议已消费）
- v5 已占用 36（24 experience + 12 development）
- `remaining_train_count` = **14**，其难度分布为 **easy 9 / medium 4 / hard 1**

因此：**从剩余官方 train 池不可能拼出 66 题的 suite，更不可能拼出难度分层的 66 题 suite。** 这不是偏好问题，是池子已枯竭。

## 6. 由此得出的选项（尚未选定，需 Critical Review）

| 选项 | 说明 | 代价 / 风险 |
|---|---|---|
| A. 复用 code-v2 的 24 题 | 已冻结、有 headroom（Vanilla 0.75）、artifact `f9c1e870…`，与 v8 dev 零重叠 | 只能测 ≥26.5pp 的效应；且已被 v2 用作 development，必须标注为**复用诊断 suite**而非 fresh held-out |
| B. 改用**严重度**主指标 | `severity = verifier.passed / 套件规模` 已在全部 evidence 中存在，实测噪声 σ=0.213–0.304；**n=24 时 MDE 降到 12–17pp**（见 §3.1） | 免费且已实现；需保留配对检验与预注册判据，因为严重度同样有噪声 |
| C. 提高每题的重复次数 | 用多次 trial 增加配对观测 | 同题重复**彼此相关**，功效增益低于名义值；不得按独立样本计算 |
| D. 换到题目充足的域 | IR/BrowseComp-Plus 有 154 train / 65 test | 官方 grader 是 temp-0.7 LLM Judge（判分噪声）；需 411MB+ 索引与 faiss/torch；磁盘余量紧张 |
| E. 用自有业务场景 | SpreadsheetBench 对账，判分确定性、效应量大概率更大 | 当前 n=3 且 4096 截断导致 0 条记忆 |

**当前建议（2026-09-14 更新）**：先用 **B（严重度主指标）+ A（复用 code-v2 的 24 题）** 做首次可归因的效果测量 —— 投递链路已由 v12 正对照证明可用（`docs/evoagentbench-positive-control-report.md`），严重度把 MDE 从 26.5pp 压到 12–17pp，因此 24 题**不再等于不可能**。必须明确标注"复用诊断 suite"身份与所报 MDE；把"证明 10pp 以下效应"的目标留给 D 或 E，而不是继续在枯竭的 train 池上硬凑题量。
